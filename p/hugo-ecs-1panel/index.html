Hugo博客搭建日记 #2 - 迁移到阿里云 ECS 并用 1Panel 托管

把 Hugo 生成的静态站点从 GitHub Pages 迁移到阿里云 ECS（Debian 12），用 1Panel 的 OpenResty 托管，包含建站、上传、域名解析、HTTPS 与备案配合的完整流程

2026-10-18T07:54
2026-10-18
阅读时长: 6 分钟

为什么要迁移

前一篇里站点是丢在 GitHub Pages 上的，省事，但有两个绕不过去的问题：一是域名解析指向的是境外 IP，访问速度和稳定性都不太可控；二是国内云服务器做 ICP 备案时，核验环节会检查域名是否真的解析到了接入商的服务器上，解析还在 GitHub 就过不了。

所以这一步做的事很简单：把本地 hugo 生成的 public 目录搬到阿里云 ECS 上，用 1Panel 里的 OpenResty 当静态服务器。整条链路没有后端程序、没有数据库，迁移成本很低。

本篇环境：阿里云 ECS（上海），Debian GNU/Linux 12，已安装 1Panel 面板。

Step 01 - 迁移前要准备的东西

项目 说明
ECS 公网 IP 后面域名 A 记录要指向它
1Panel 面板地址 http://ECS公网IP:面板端口/安全入口
本地 Hugo 环境 能正常执行 hugo 命令
域名 已注册，能改 DNS 解析

1Panel 的网站功能依赖应用商店里的 OpenResty，不是系统自带的 nginx。如果面板里还没装，先到「应用商店」搜 OpenResty 安装，否则「网站」菜单建站会失败。

Step 02 - 在 1Panel 里创建静态网站

  1. 打开 1Panel，左侧菜单进入 网站 → 创建网站。

  2. 网站类型选 静态网站。

  3. 域名填 snackbs.asia 和 www.snackbs.asia（一行一个，或者用逗号分隔，具体以面板提示为准）；备案还没下来之前，这里也可以先填 ECS 的公网 IP 做测试。

  4. 网站目录保持默认即可，1Panel 会在安装目录下生成对应路径，形如：

1

/opt/1panel/apps/openresty/openresty/www/sites/snackbs.asia/index

如果你的 1Panel 装在 /data 下，路径会变成 /data/1panel/apps/openresty/openresty/www/sites/...。以面板里「网站目录」实际显示的为准，别照抄。

  1. 其他选项（PHP、伪静态、SSL）先不用管，创建完成。

创建好之后，1Panel 会自动往 OpenResty 的配置里加一个 server 块，站点根目录就是你刚才看到的那个 index 文件夹。

Step 03 - 上传构建产物

3.1 本地生成 public

在站点根目录执行：

1

hugo --minify

生成的整站文件都在 public 目录里，全是静态文件，不需要 Hugo、不需要 Node.js 就能跑。

上传前检查 hugo.yaml 里的 baseurl 必须和最终访问地址一致（比如 https://snackbs.asia/，注意结尾斜杠）。写错了会出现 CSS 能加载但图片全裂、或者链接跳到旧域名的现象。

另外 public 里如果有 CNAME 文件，那是 GitHub Pages 专用的，上传到 ECS 前删掉。

3.2 打包上传

本地把 public 打成压缩包，然后通过 1Panel 的文件管理器上传：

  1. 进入 1Panel 左侧 文件，定位到网站目录 .../www/sites/snackbs.asia/index。

  2. 先把目录里 1Panel 默认生成的 index.html 之类占位文件删掉。

  3. 上传压缩包，右键解压，把内容铺到这个目录下（保证 index.html 直接位于该目录，而不是多套一层 public）。

服务器没装解压工具的话，先在终端执行：

1

apt update && apt install -y unzip

站点文件比较多或者想少点手动操作时，用 rsync 更省事（本地终端执行）：

1

rsync -avz --delete ./public/ root@ECS公网IP:/opt/1panel/apps/openresty/openresty/www/sites/snackbs.asia/index/

--delete 会清掉服务器上多余的老文件，配合 public 的完整产物使用，能避免旧页面残留。第一次用之前务必确认路径没错，这个参数是会真删东西的。

3.3 权限

解压完如果访问是 403，先看权限。站点目录用 755 最稳妥：

1

chmod -R 755 /opt/1panel/apps/openresty/openresty/www/sites/snackbs.asia/index

目录和文件都给 755 就够读了，不放可执行脚本的静态站点不需要更宽的权限。

Step 04 - 域名解析

到域名服务商的控制台加两条 A 记录：

主机记录 类型 记录值 TTL
@ A ECS 公网 IP 600
www A ECS 公网 IP 600

TTL 先设小一点（600 秒），方便出问题时快速回滚。

生效后本地验证：

1
2

nslookup snackbs.asia
dig +short snackbs.asia

返回的是 ECS 公网 IP 就对了。注意 GitHub Pages 时代留下的解析记录要删干净，尤其是那条指向 185.199.x.x 的 A 记录。

解析改完到全量生效通常要几分钟到几十分钟，受 TTL 和各地 DNS 缓存影响。这期间不同网络下访问结果可能不一致，别急着判断配置错了。

Step 05 - 开放端口与 HTTPS

5.1 安全组

阿里云控制台 → ECS 实例 → 安全组，入方向只放必要的端口：

端口 用途 来源
80 HTTP（含证书申请验证） 0.0.0.0/0
443 HTTPS 0.0.0.0/0
1Panel 面板端口 面板管理 只填自己常用的出口 IP，不要放 0.0.0.0/0
SSH 端口 运维 同上，尽量收窄

最小原则：能填 /32 的就不填 0.0.0.0/0。面板端口和 SSH 端口暴露在公网被撞库是很常见的事，收窄来源比改复杂密码更有效。

5.2 申请证书

1Panel 里进入 网站 → 点网站名 → HTTPS：

  1. 选择 Let’s Encrypt，勾选 snackbs.asia 和 www.snackbs.asia。

  2. 验证方式选 HTTP 验证（要求 80 端口对外开放，且域名已经解析到本机）。

  3. 申请成功后打开 强制 HTTPS。

申请失败最常见的原因就两个：80 端口没在安全组放行，或者域名还没解析过来。证书有效期 90 天，1Panel 默认会自动续期，留意面板里的到期提醒就行。

如果域名还没备案，阿里云会对 80 端口的域名访问做拦截，页面会跳到一个提示页，这是正常的，不代表站点配置有问题。备案通过后会自动放行。这期间想先看效果，可以在本地 hosts 里把域名指到 ECS IP，用 443 访问。

Step 06 - 备案期间要注意的几件事

迁移到 ECS 之后，备案核验看的是这几样东西，提前对齐能少跑一趟：

  1. 域名必须解析到这台 ECS。这是最容易被打回的一项，解析还在别处就是「未接入」。

  2. 网站要能正常打开，并且首页标题和备案填报的「网站名称」一致。本站标题统一是 snackbs小站，页面上看到的和填报的要对得上。

  3. 备案期间别关站。核验人员会实际访问，打不开或者只是个空白页都可能被判为无效网站。

  4. 网站内容要和备案信息匹配。个人博客就写博客内容，别混进论坛、商城、下载站这类需要前置审批的形态。

  5. 备案通过后 30 日内到公安备案系统做联网备案，这是独立于 ICP 的另一套流程。

Step 07 - 日常更新流程

迁移完成后，发文章的流程变成三步：

  1. 本地写 Markdown，hugo server 预览。

  2. hugo --minify 生成 public。

  3. 把 public 同步到服务器站点目录。

手动 rsync 足够用。如果嫌麻烦，也可以在 GitHub Actions 里加一步：构建完用 rsync + SSH 私钥（存到仓库 Secrets）直接推到 ECS。思路和原来的 GitHub Pages 部署一致，只是最后一步的目标从仓库换成了服务器目录。

1Panel 的文件管理器和计划任务里也有现成的备份功能，站点目录可以定期打包存到对象存储，成本很低。

Step 08 - 常见问题

访问 403：目录权限不对，或者 index.html 不在站点根目录（多套了一层文件夹）。

访问 404：1Panel 里网站的根目录和实际放文件的目录不是同一个，回面板核对「网站目录」。

页面能开但样式全乱：baseurl 和实际访问的协议/域名不一致，Hugo 生成的是绝对路径，改完重新 hugo 构建再传。

图片 404，其他正常：检查图片是否一起上传了（public 里应该带 images/p 等目录），以及文件名里有没有 #、? 这类在 URL 中有特殊含义的字符。

证书申请一直失败：先确认 80 端口能从公网访问，再确认域名解析指向的是这台机器，最后看 1Panel 里有没有别的站点占用了 80。

改了文件但浏览器还是旧的：清浏览器缓存，或者在 1Panel 网站设置里清理缓存；用了 CDN 的话还要在 CDN 侧刷一下。

1Panel 面板打不开：面板端口的安全组规则是不是被自己改没了，或者面板服务没起来（终端 systemctl status 1panel 看状态）。

小结

迁移这件事本身没什么技术含量，核心就是把 public 目录换一个地方放：原来的地方叫 GitHub Pages，现在叫 ECS 上的一个文件夹，外面套一层 OpenResty。

真正需要花心思的是迁移之后的两件事——域名解析要指向这台机器，站点要能稳定打开。这两条既决定备案能不能过，也决定后面所有事情能不能继续往下走。
